# 裁撤评审工程文档

> 一份"减法"评审：盘点项目中**臃肿、重复、零收益**的部分，给出裁撤/冻结/收敛建议。
> 与 [RAG优化工程文档.md](RAG优化工程文档.md)（加法账本）互补——两者合起来回答
> "这个项目该往哪长、该在哪里止"。

---

## 1. 评审原则

**裁撤判据**（满足任一即进入评审）：

1. **死重复**：同一信息/能力存在两个来源，改一个漏一个；
2. **零使用**：功能存在但没有任何路径真实使用；
3. **被覆盖**：能力已被更好的实现取代，旧实现只剩兼容负担；
4. **认知负担**：使用者需要理解的概念数量超过了功能带来的价值。

**价值定义**：这是个人学习/面试项目——学习价值、面试叙事价值算真实价值，
不搞"能删就删"。因此每项裁定都写明"为什么值得/不值得留"。

**裁定分级**：🔴 裁撤（Cut）/ 🟡 冻结（Freeze，停止演进）/ 🔵 收敛（Merge）/ 🟢 保留观察。

## 3. 裁撤详情

### CUT-01 删除 requirements.txt / requirements-ocr.txt 🔴

- **现状**：`requirements.txt`（charset-normalizer、dotenv、PyMuPDF、pytest）和
  `requirements-ocr.txt`（前者 + Pillow/pytesseract）与 pyproject 的核心依赖和
  `pdf/ocr/dev` extras **逐项重复**；README 的安装路径两者都教。
- **臃肿理由**：双来源违反单一事实源——改 pyproject 忘改 txt 就会出现
  "两种安装方式装出不同环境"（死重复）。历史上 txt 先于 pyproject 存在，
  pyproject 成熟后它只剩"源码检出免构建"的边际便利，而 `pip install .`
  并不构成障碍。
- **方案**：删除两个文件；README/setup.sh 统一为 `python -m pip install -e ".[all]"`
  路径；OCR 说明并入 pyproject 注释（已有）。
- **风险与迁移**：极低。检索文档内 `requirements` 引用并更新。

### CUT-02 删除 pyproject 的 `text` extra 🔴

- **现状**：`text = ["charset-normalizer>=3.0"]`——但 charset-normalizer>=3.3
  就在核心 dependencies 里。
- **方案**：删除该 extra；`all` 里对应项随核心依赖自然覆盖。
- **风险**：零。

### CUT-03 清理 Chunk/TextBlock 的废弃别名字段 🔴

- **现状**：`TextBlock.source_char_start/end` 与 `Chunk.char_start/end` 是
  v0.1 的旧名，v0.2 起被 `normalized_char_*` 取代，现在仅在 `__post_init__`
  里做双向镜像（models.py 中 6 处 setattr 逻辑只为兼容旧名）。
- **臃肿理由**：序列化输出里每个 chunk 多存 2-4 个恒等重复字段（死重复），
  新读者还要理解"两个名字哪个是真的"（认知负担）。
- **方案**：删除别名字段与镜像逻辑，`to_dict` 只输出规范名；chunk_id 的计算
  不含这些字段，**索引与增量复用不受影响**；旧 JSONL 里多出的键在加载时
  本就被忽略，无需迁移。
- **风险**：低。iOS 仓库的 Swift 契约若镜像了别名字段需同步（单独小提交）。

### CUT-04 移除 evaluate 报告中的 citation proxy 🔴

- **现状**：`evaluation.py` 输出 `citation_accuracy`（检索层引用正确率代理）；
  harness 的 `citation_validity`（四态、基于真实回答）是严格更强的版本。
- **臃肿理由**：两个同名不同物的"引用指标"并存，README 还要专门解释
  "citation proxy 不等于事实正确率"（被覆盖 + 概念混淆）。
- **方案**：`evaluate` 保留 Recall@K（及 OPT-02 的 MRR/nDCG），移除
  citation_accuracy；文档与测试同步。引用质量一律看 harness。
- **风险**：低。涉及 1 个测试断言与 README/使用指南措辞。

### CUT-05 合并 agent 的 --save-history 进 --history 🔴

- **现状**：`--history`（读取+写回）与 `--save-history`（只写不读）两个旗标，
  差异场景（"不读旧历史但写到新路径"）极少使用。
- **方案**：删除 `--save-history`，`--history` 语义不变；需要"只写"时先删旧文件。
- **风险**：破坏性极小（个人项目，grep 无外部使用）。

### CUT-06 删除 `version` 子命令 🔴

- **现状**：子命令 `rag-agent version` 与旗标 `--version` 输出完全相同。
- **方案**：删子命令，保留 `--version`（Unix 惯例）。测试改测旗标。

### CUT-07 .env 模板单一来源化 🔴

- **现状**：`.env.example`（根目录）与 `workspace.py:ENV_TEMPLATE`（init 生成）
  是两份几乎相同的模板，改一处漏一处。
- **方案**：删除 `.env.example`；`scripts/setup.sh` 改为调用 `rag-agent init`
  生成 `.env`（该命令本就幂等且保留已有文件）；README 的 `cp .env.example`
  步骤换成 `rag-agent init`。

## 4. 冻结与收敛

### FRZ-01 LangGraph runtime：冻结为实验路径 🟡

- **现状**：手写循环（默认）与 LangGraph 图（`--graph`）双 runtime。图路径
  当前**没有使用任何 LangGraph 独有能力**（无 checkpointer、无人工介入、
  无持久化），却要求每次工具逻辑改动双端同步——M2 抽共享 dispatch 正是为
  消除这种漂移成本。
- **裁定理由**：不裁（学习与面试价值真实：contract-first 的最佳对照实验），
  但**冻结**：停止为其添加新特性，CLI help 与文档标注"实验路径"；触发条件——
  若落地 checkpointer/断点恢复等真实需求则解冻，否则 6 个月后复审删除。
- **立即收益**：新功能（如 OPT-17 结构化判别器）只需考虑手写路径。

### FRZ-02 chinese embedding：条件裁撤 🟡

- **现状**：`chinese`（n-gram 基线）与 `hash`（默认基线）都是离线弱 embedding。
- **裁定**：OPT-09 神经 embedding 落地之日，`chinese` 即为死基线 → 届时删除
  provider、测试与文档引用，`hash` 保留为离线默认。**现在不动**（尚有真实使用）。

### MRG-01 evaluate / harness 格式收敛 🔵

- **现状**：`retrieval.jsonl`（evaluate）与 `agent_tasks.jsonl`（harness）两套
  相似 schema；指标分散在 evaluation.py 与 harness/metrics.py。
- **方案**：借 OPT-02（补 MRR/nDCG）之机统一——harness 的题库格式为唯一
  格式（它已是 evaluate 格式的超集），指标函数共享；`evaluate` 保留为
  "纯检索、无 agent" 的轻量入口。
- **时机**：与 OPT-02 同一提交，避免两次破坏格式。

### MRG-02 ingest / ingest-url 共享参数组 🔵

- `--max-chars/--overlap-chars/--max-file-mb` 等在两个命令重复定义 → 提取
  `_add_chunking_arguments()`，随下次触碰这两个命令时顺手做。
