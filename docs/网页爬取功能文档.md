# 网页爬取功能文档

一句话用法：`rag-agent ingest-url https://example.com` —— 爬取该网站的文字内容，
清洗整理成知识块，存入本地向量索引，之后 `search` / `ask` / `chat` 就能检索和引用
这些网页内容。

本文档分两部分：**设计思路**（为什么这样做）和**函数讲解**（每个模块怎么实现）。
阅读前建议先了解 [rag-guide/02_资料导入与数据契约.md](rag-guide/02_资料导入与数据契约.md)
中的数据契约概念。

---

## 1. 设计思路

### 1.1 整体数据流

```text
输入 URL
  → 爬虫调度（crawler.py）          广度优先、同域、robots.txt、限速
    → 单页下载（fetch.py）          http/https GET，限大小，按响应头解码
      → 清洗整理（extract.py）      去噪、抽正文、标题栈、HTML → TextBlock
        → 数据契约（models.py）     DocumentRecord(source_path=URL, file_type=html)
          → 合并（ingest_url.py）   与既有 chunks/manifests 合并
            → 分块 → 向量索引       chunk_document + update_vector_index（复用旧向量）
              → search / ask / chat 正常检索引用
```

### 1.2 关键决策一：爬取用确定性流水线，不用 LLM 驱动

需求里说的 "Agent" 在这里实现为**受控的自动抓取流水线**，而不是让大模型决定爬哪里。
原因：

1. **礼貌与边界必须强制**：robots.txt、同域限制、页数上限、请求间隔这些约束面对
   真实网站时必须被硬性执行，不能依赖模型自觉；
2. **成本与速度**：爬取是 I/O 密集任务，LLM 决策每一步既慢又花钱，且收益几乎为零
   ——"找站内链接并抓取"本身不需要智能；
3. **可复现、可离线测试**：确定性调度让同样的 URL 每次抓取结果一致，失败清单可解释，
   单元测试用假 fetcher 就能模拟整站（本功能的 8 个测试全部离线运行）。

大模型在整条链路里只出现在它真正有价值的地方：`ask` / `chat` / `agent` 的问答层。

### 1.3 关键决策二：网页直接复用现有数据契约

网页不另建一套存储，而是清洗后直接产出 `DocumentRecord`（和 PDF/Markdown 一样）：

| 网页概念 | 数据契约字段 | 好处 |
| --- | --- | --- |
| 页面 URL | `source_path` | 检索引用直接显示来源网址 |
| 页面类型 | `file_type="html"` | `search --file-type html` 可过滤 |
| 原始字节哈希 | `content_hash` | 重爬时判断内容是否变化 |
| `<title>` + `h1`-`h6` | `TextBlock.heading_path`（标题栈） | 引用能显示"来源 URL，章节：xxx" |
| 清洗配置版本 | `ingestion_fingerprint` | 清洗逻辑升级后自动重新分块，不混用旧数据 |

这一决策让分块、引用、增量导入、评测**一行代码都不用改**。

### 1.4 关键决策三：增量复用向量，重复爬取不重复花钱

`chunk_id` 由 `source_id(URL) + content_hash + 分块配置指纹` 确定性生成（见
`chunking/splitter.py`）。因此：

- 同一页面内容没变 → 重新爬取生成的 `chunk_id` 与旧索引完全相同 →
  `update_vector_index` 直接复用旧向量，**不调用任何 embedding 服务**；
- 内容变了 → 只有该页面的新 chunk 需要重新 embedding，其他页面不受影响。

第二次执行 `ingest-url` 同一 URL 的输出里 `vectors_embedded=0`，就是这一机制生效
的证据（有测试断言这一点）。

### 1.5 关键决策四：默认保守的礼貌抓取

| 边界 | 默认值 | 理由 |
| --- | --- | --- |
| `robots.txt` | 遵守 | 站点的明示意愿；`--no-robots` 仅应用于你自己的站点 |
| 抓取范围 | 同域 | 跟着链接跑到外网既失控又失礼；`--cross-domain` 需显式开启 |
| 请求间隔 | 1 秒 | 并发轰炸对对方服务器不友好，也可能触发封禁 |
| 页数上限 | 10 页 | 防止失控；想爬全站显式调大 `--max-pages` |
| 链接深度 | 1 层 | 先看入口页的直接链接，确认有价值再加深 `--max-depth` |
| 单页大小 | 5 MiB | 超限直接失败而不是截断，避免把半个页面当完整内容导入 |

robots.txt 拿不到时选择放行：此时单页上限和同域约束仍然兜底；站点明确禁止的
页面会记入失败清单（`error_type=robots-disallowed`），可解释、可核对。

### 1.6 清洗策略与取舍

- **去噪**：移除 script/style/iframe/form/nav/header/footer/aside，以及带
  `role=navigation|banner|contentinfo` 或 `aria-hidden=true` 的区块；
- **正文容器**：优先 `<main>`，其次 `<article>`，都没有就退回 `<body>` 并在
  manifest 里记 `no-semantic-container` 警告（提醒"这页可能是整页噪声"）；
- **列表**：嵌套列表深度优先展开为独立块，先父项后子项，内容不重复不丢失；
- **表格**：压成逐行文本（单元格用 ` | ` 连接），保留可读性；
- **空白**：连续空白合并为单空格，CJK 文本不受影响；
- **纯文本容器**：没有结构子元素的 div/span 整体作为一个语义块——很多站点
  （尤其 JS 渲染的 SPA）把正文放在 span/div 里而不是 `<p>` 里。

已知取舍：JavaScript 渲染的内容默认抓不到，需要 `--render-js`（见第 5 节）。

### 1.7 动态渲染抓取（--render-js，可选）

动态网站返回的 HTML 是空壳，内容由浏览器里的 JavaScript 现场生成。`render.py`
提供无头浏览器（Playwright + Chromium）抓取路径：

```text
URL → 静态请求（robots.txt/非 HTML 资源直接返回，404 在此暴露）
    → HTML 页面 → Chromium 渲染 → 等 JS 执行 → 最终 DOM
    → 与静态路径完全相同的清洗/分块/索引链路
```

- 是**可选依赖**（`[web-js]` extra + `playwright install chromium`，浏览器体积
  大，刻意不进 `all`）；未安装时在创建阶段就报明确错误，不会爬到一半失败；
- 抽取器收到的就是"浏览器看到的最终 DOM"，之后的清洗、标题栈、增量复用与
  静态路径零差异；
- 真实 A/B 验证（quotes.toscrape.com/js/）：静态抓取只得 5 字符（"Login"），
  `--render-js` 抓到全部 11 个名言块（1426 字符）并可检索。

## 2. 模块与函数讲解

代码位于 `src/rag_agent/webfetch/`，四个模块各管一段数据流。

### 2.1 `fetch.py` —— 单页下载

| 函数/类型 | 职责 |
| --- | --- |
| `normalize_url(url)` | 规范化：只允许 http/https，去 fragment，scheme/host 转小写。所有身份计算和去重的基石。 |
| `source_id_for_url(url)` | 由规范化 URL 生成来源身份。与 `models.source_id_for_path` 同构但不能复用它——后者会把 URL 当本地路径做 `Path.resolve`，得到跨机器不稳定的身份。 |
| `fetch_url(url, timeout, max_bytes, user_agent)` | 真实 HTTP GET。校验 Content-Type（只收 text/html、application/xhtml+xml、text/plain），按响应头字符集解码，超限抛 `WebFetchError` 而不是截断。 |
| `FetchResult` | 成功下载的不可变结果：原始 `body` 字节（供内容哈希）+ 解码后 `text`（供抽取）。 |
| `WebFetchError` | 可预期错误（网络/协议/类型/超限），爬虫捕获后记入失败清单，不让整次抓取崩溃。 |

### 2.2 `extract.py` —— 清洗整理

| 函数 | 职责 |
| --- | --- |
| `extract_blocks(html)` | 纯函数：HTML → `[(正文文本, 标题路径), ...]` + warnings + 页面标题。内部先 `_clean_soup` 去噪、`_pick_container` 选正文容器，再递归 `walk`：遇到标题就维护标题栈，遇到块级元素就产出文本。 |
| `build_web_document(page)` | `FetchResult` → `DocumentRecord`。生成 source_id/doc_id/content_hash/指纹，把每个 block 的字符偏移如实记录在"规范化全文"中（块间以空行分隔），供分块器生成引用区间。纯文本页（text/plain）按空行切段，heading_path 为空。 |
| `extract_links(html, base_url)` | 抽取页面链接供爬虫调度：相对链接绝对化、去 fragment/mailto/javascript、保序去重。 |
| `_iter_list_items(list_node)` | 嵌套列表的处理：先把嵌套的 ul/ol 从父项里 `extract()` 摘出来再取父项文本，然后递归展开被摘出的子列表——内容不重复也不丢失。 |

BeautifulSoup 是可选依赖（`[web]` extra）；`_require_bs4()` 在缺失时给出明确的
安装提示，与 PDF（PyMuPDF）、OCR（pytesseract）的处理模式一致。

### 2.3 `crawler.py` —— 抓取调度

| 函数/类型 | 职责 |
| --- | --- |
| `CrawlConfig` | 一次抓取的全部边界参数（上限/深度/间隔/robots/同域），带参数合法性校验。 |
| `crawl_site(start_url, config, fetcher=None, sleep=time.sleep)` | 核心 BFS：从入口出发，出队→robots 检查→抓取→入队站内新链接（深度+1，直到 `max_depth`）。`fetcher` 和 `sleep` 可注入——测试传入假 fetcher 和记录器即可模拟整站，这就是"完全离线可测"的实现方式。 |
| `_RobotsCache` | 按站点缓存 robots.txt 解析结果；`allows(url)` 返回（是否允许，站点 crawl-delay）。抓不到 robots.txt 时放行。 |
| `CrawlResult` | `pages`（成功）/ `failures`（失败+原因）/ `queued`（进过队列的 URL 总数）。单页失败不阻塞其他页面，与文件导入的失败清单语义一致。 |

细节：第一个请求之前不休眠；`delay_seconds` 与 robots 的 crawl-delay 取较大值。

### 2.4 `ingest_url.py` —— 与既有索引合并

| 函数 | 职责 |
| --- | --- |
| `merge_web_documents(records, existing_chunks, existing_manifests, chunk_config)` | 合并快照：这次抓到的 URL 用新 chunks 替换旧 chunks；没抓到的 URL 的既有数据原样保留（重新爬一个入口不应该隐式删除别的页面）。同时统计每个 URL 属于 added / updated / unchanged 哪一类。 |
| `WebMergeCounts` / `WebMergeResult` | 合并统计，最终打进 CLI 的 JSON 摘要。 |

### 2.5 `render.py` —— 动态渲染抓取（可选）

| 函数/类型 | 职责 |
| --- | --- |
| `create_render_fetcher(...)` | 创建真实 Chromium 渲染抓取器；Playwright 缺失或浏览器未安装时**在创建阶段**就抛出带安装指引的 `WebFetchError`，而不是爬到一半失败。 |
| `RenderFetcher` | 符合 `crawl_site(fetcher=...)` 约定。`__call__` 先走静态路径：robots.txt、text/plain 等非 HTML 资源直接返回（浏览器零消耗），只有 HTML 页面交给渲染引擎；渲染结果用 `page.url`（重定向后的最终地址）和 `page.content()`（最终 DOM）。`page_renderer` / `static_fetcher` 均可注入，测试完全离线。 |
| `_build_playwright_renderer` | 启动一次 Chromium、复用同一个 browser context（整个抓取会话只启动一次浏览器）；`wait_until="networkidle"` 等待 JS 与 XHR 完成，超时自动退回 `load` 事件（常驻连接的站点会卡住 networkidle）。 |

### 2.6 CLI 层 `ingest-url`（`cli.py:_handle_ingest_url`）

把以上模块串起来：抓取 → 逐页 `build_web_document`（单页失败进清单）→
`merge_web_documents` → 原子写 chunks/manifests/failures →
`update_vector_index`（复用未变化向量）→ 打印 JSON 摘要。有失败时退出码为 2，
与 `ingest` 保持一致。

## 3. 使用示例

```bash
# 最常用：抓入口页 + 它的直接链接（默认 10 页、深度 1、间隔 1 秒）
rag-agent ingest-url https://docs.example.com/tutorial

# 爬深一点、多一点（注意礼貌：别对别人的站点开大并发）
rag-agent ingest-url https://docs.example.com/tutorial --max-pages 50 --max-depth 2

# 先只抓入口页看看整理质量，再决定要不要扩大
rag-agent ingest-url https://docs.example.com --max-pages 1 --no-index

# 抓自己的站点（忽略 robots 限制）
rag-agent ingest-url https://my-site.example.com --no-robots

# 动态渲染站点（内容由 JS 生成的页面）
python -m pip install -e ".[web-js]" && python -m playwright install chromium   # 一次性
rag-agent ingest-url https://spa.example.com --render-js

# 爬完正常提问，引用会显示 URL
rag-agent ask "这份教程里怎么配置超时？"
```

排查失败页：`data/failed/ingestion.jsonl` 里每行一个失败 URL 和原因
（robots 拒绝、404、超限、Content-Type 不支持……）。

## 4. 测试策略

`tests/unit/test_webfetch.py`，8 个测试全部离线：

- **抽取**：固定 HTML 夹具 → 断言噪声被移除、标题栈正确（`测试站点 > 讲义 > 章节`）、
  列表展开、链接绝对化、DocumentRecord 字段与确定性；
- **爬虫**：字典当整站（URL → 内容）注入假 fetcher，断言 BFS 顺序、深度、同域过滤、
  robots 拦截进失败清单、`max_pages` 截停、单页 404 不阻塞；
- **CLI 端到端**：同一假站点跑两遍 `ingest-url`，第一遍断言索引可被 `search` 命中且
  `vectors_embedded == chunks_written`，第二遍断言 `pages_unchanged=1` 且
  `vectors_embedded=0`（增量复用生效）。

## 5. 已知边界与后续优化

- **需要登录的页面抓不到**：静态与渲染路径都没有登录态；可考虑增加 cookie 注入；
- **无限滚动/虚拟列表**：渲染模式只取首屏 DOM，滚动加载的内容需要专门的翻页/滚动逻辑；
- **没有 sitemap/RSS 支持**：目前只沿 `<a>` 链接走，读 sitemap.xml 可以更快覆盖全站；
- **子域被同域规则排除**：`a.example.com` 和 `b.example.com` 视为不同域（可 `--cross-domain`）；
- **raw HTML 不归档**：目前只存清洗后的文本，如需"证据原件"可加 HTML 快照目录；
- **渲染是重量级路径**：Chromium 内存与启动开销显著，页面多时明显慢于静态抓取，
  只在确有需要时使用。
