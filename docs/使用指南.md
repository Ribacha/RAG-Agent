# rag-agent 使用指南

这份文档只回答一个问题：**我平时想用这个工具的时候，该敲什么命令**。

按场景组织，可以直接照抄。项目的技术说明见根目录 [README.md](../README.md)。

---

## 0. 使用前记住一条原则

> **先 `search` 确认能命中，再 `ask` 让模型回答。**

`search` 和 `--dry-run` 完全离线、不消耗 Key；`ask` 和 `agent` 会调用 DeepSeek（花一点钱）。
检索没命中就先调资料或换个问法，别急着问模型——证据不对，回答一定不对。

---

## 1. 每次开始：两步准备

打开终端后先做这两步（换个新终端窗口就要重新做）：

```bash
cd "/Users/Zhuanz/Documents/AI Agent/rag-agent"   # 进入项目目录
source .venv/bin/activate                          # 激活虚拟环境
```

激活成功的标志：命令行提示符前面出现 `(.venv)`。

如果懒得激活，也可以全程用完整路径代替，如 `.venv/bin/rag-agent ask ...`，效果完全一样。

不确定环境是否正常时，先跑自检（永远不花钱）：

```bash
rag-agent doctor
```

全部 ✅ 就可以用了；⚠️ 是提醒（比如没装 OCR），❌ 才是必须修复的问题。

## 2. 场景一：问知识库问题（最常用）

### 方式 A：一次性提问

```bash
# 第 1 步：先看检索能不能命中（离线，不花钱）
rag-agent search "TCP 三次握手的流程是什么" --top-k 5

# 第 2 步：命中了，再让 DeepSeek 回答（花少量 API 费用）
rag-agent ask "TCP 三次握手的流程是什么" --top-k 5
```

- `search` 会打印每条证据的相似度分数（`score=`）、来源文件和页码，你自己判断靠不靠谱；
- `ask` 的回答会带 `[1]`、`[2]` 引用编号，回答末尾列出每个编号对应的文件、页码和章节；
- `--top-k 5` 表示取最相关的 5 条证据，想要更多更少随时改数字。

**想先看看会发给模型什么、又不想花钱？**

```bash
rag-agent ask "TCP 三次握手的流程是什么" --dry-run
```

只检索并展示证据，不调用模型。Key 有问题、网络有问题时，也用它来区分"本地坏了"还是"在线部分坏了"。

### 方式 B：交互式聊天（推荐日常使用）

连续问多个问题、想追问时用这个，不用每问一次敲一长串命令：

```bash
rag-agent chat
```

进入会话后：

| 你输入 | 发生什么 |
| --- | --- |
| 一个问题 + 回车 | 检索并回答（调用 DeepSeek） |
| `/search 关键词` | 只检索不回答（离线） |
| `/reset` | 清空当前会话上下文，重新开始 |
| `/help` | 查看可用命令 |
| `exit`（或 Ctrl+C） | 退出会话 |

### 进阶：agent 模式

普通 `ask` 是"检索一次→回答"；`agent` 模式让模型自己决定检索什么、检索几次，适合需要综合多处资料的复杂问题：

```bash
rag-agent agent "对比一下流量控制和拥塞控制的区别" 
```

建议：普通 `ask` 能答好的问题就用 `ask`，更便宜更快。

## 3. 场景二：往知识库里加新资料

三步：

```bash
# 1. 把文件放进收件箱（支持 PDF、Markdown、TXT）
cp /你的路径/新资料.pdf data/inbox/

# 2. 增量导入：只处理新增和变化的文件，旧的不会重算
rag-agent ingest data/inbox --incremental

# 3. 验证一下新资料能被搜到
rag-agent search "新资料里的某个关键词"
```

导入完成后 `data/index/` 里的索引自动更新，不需要再做别的。

**查看现在知识库里都有什么：**

```bash
rag-agent list-documents
```

**删掉资料怎么办？** 直接把文件从 `data/inbox/` 移走，再跑一次 `rag-agent ingest data/inbox --incremental`，对应内容会从索引中清除。

## 4. 场景三：把一个网站变成知识库

输入一个网址，工具会自动爬取站点内的文字内容、清洗整理后存进索引：

```bash
# 先安装网页抓取依赖（一次性）
python -m pip install -e ".[web]"

# 抓入口页 + 它的直接链接（默认同域、遵守 robots.txt、每秒最多 1 个请求、最多 10 页）
rag-agent ingest-url https://docs.example.com/tutorial

# 觉得内容有价值后，爬得更深更多
rag-agent ingest-url https://docs.example.com/tutorial --max-pages 50 --max-depth 2
```

要点：

- 重复执行**不重复花钱**：内容没变的页面自动复用旧向量，只有新增或变化的页面重新计算；
- 之后 `search` / `ask` / `chat` 照常使用，回答的引用里显示的是**来源网址**；
- 某些页面没抓到？看 `data/failed/ingestion.jsonl`，每行都有失败原因（robots 拒绝、
  404、页面超限等）；
- 只支持静态网页；JavaScript 渲染的站点暂时抓不到。

## 5. 场景四：完全不花钱的使用方式

下面这些全部离线运行，不用 Key、不联网：

```bash
rag-agent doctor                                  # 环境自检
rag-agent search "任何问题" --top-k 5              # 纯检索
rag-agent ask "任何问题" --dry-run                 # 检索 + 查看证据
rag-agent chat --retrieval-only                   # 交互式纯检索会话
rag-agent ingest data/inbox --incremental         # 导入资料
rag-agent list-documents                          # 查看已导入清单
```

只有 `ask`（不带 `--dry-run`）、`agent`、`chat`（不带 `--retrieval-only`）调用 DeepSeek。

## 6. 常用命令速查表

| 命令 | 干什么 | 花钱吗 |
| --- | --- | --- |
| `rag-agent doctor` | 自检环境、配置、索引 | 否 |
| `rag-agent search "问题"` | 检索最相关的知识片段 | 否 |
| `rag-agent ask "问题"` | 检索 + DeepSeek 回答 | **是** |
| `rag-agent ask "问题" --dry-run` | 只看将发送的证据 | 否 |
| `rag-agent chat` | 交互式问答会话 | **是** |
| `rag-agent chat --retrieval-only` | 交互式纯检索 | 否 |
| `rag-agent chat --agent` | 交互式 + agent 模式 | **是** |
| `rag-agent agent "问题"` | 模型自主多步检索问答 | **是** |
| `rag-agent ingest data/inbox --incremental` | 增量导入资料 | 否 |
| `rag-agent ingest-url 网址` | 爬取网站内容并导入索引 | 否 |
| `rag-agent list-documents` | 查看已导入文档清单 | 否 |
| `rag-agent rebuild-index` | 用现有 chunks 重建索引 | 否 |
| `rag-agent evaluate 评测集.jsonl` | 离线评测检索质量 | 否 |

### 常用微调选项（加在命令末尾）

| 选项 | 作用 | 什么时候调 |
| --- | --- | --- |
| `--top-k 8` | 检索条数（默认 5） | 问题复杂、需要更多证据时调大 |
| `--min-score 0.05` | 相似度门槛（ask 默认 0.08） | 该命中的没命中→调低；检索到不相关的→调高 |
| `--file-type pdf` | 只搜某种类型文件 | 混合资料库想缩小范围 |
| `--json` | 机器可读输出 | 需要程序处理结果时 |

## 7. 常见问题

**问：提示 `ModuleNotFoundError: No module named 'rag_agent'`**
环境出问题时（比如同步软件动了 `.venv`），重装一次即可：
```bash
.venv/bin/python -m pip install . -q
```

**问：回答里出现"知识库中没有找到足够相关的内容"**
不是报错，是拒答保护——说明检索没有命中足够相关的证据。依次检查：
1. `rag-agent list-documents` 确认资料已导入；
2. `rag-agent search "同一个问题"` 看检索结果；
3. 换个更贴近原文措辞的问法，或把 `--min-score` 调低一点试试。

**问：怎么知道一条回答依据的是什么？**
看回答末尾的引用列表：`[1] 文件路径，第 N 页`。对不确定的回答，翻到对应页码核对原文。

**问：API Key 报错（401/403）**
Key 失效或余额不足。编辑项目根目录的 `.env` 文件更新 `LLM_API_KEY`，改完重新运行命令即可。

**问：换了新电脑 / 新目录想用？**
在仓库里 `bash scripts/setup.sh` 一键装好；或者在任何目录 `rag-agent init` 创建独立工作区（会生成自己的 `data/` 和 `.env`）。

## 8. 检索不准怎么办？（当前已知限制）

当前索引用的是离线 `hash` embedding，它只做字面匹配级别的相似度，**不真正理解中文语义**，所以：

- 换个说法问同一件事，命中率可能下降；
- 沾边但不精准（比如问"三次握手"命中"流量控制"的段落）。

**当下的实用技巧**：提问时多用资料里出现过的原词（比如问"三次握手"而不是"连接怎么建立的"）。

**根本解决**：优化文档 [RAG优化工程文档.md](RAG优化工程文档.md) 阶段二计划接入神经 embedding 和混合检索，到时候检索质量会有质的提升。
