# 本项目源码阅读与动手路线

这篇文档把前面的概念落到当前仓库。建议每完成一个实验，就检查生成文件和测试结果，不要一次跳到 Agent。

## 1. 准备环境

```bash
cd "/Users/Zhuanz/Documents/AI Agent/rag-agent"
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
export PYTHONPATH=src
```

如果要调用 DeepSeek：

```bash
python -m pip install -e ".[llm]"
```

先确认 CLI：

```bash
python -m rag_agent --help
```

## 2. 实验一：只导入，不接模型

准备一个简单文件：

```text
data/inbox/sample.md
```

内容可以是：

```markdown
# TCP

## 三次握手

TCP 通过三次握手建立连接。客户端先发送 SYN，服务器返回 SYN-ACK，客户端再发送 ACK。
```

执行：

```bash
python -m rag_agent ingest data/inbox
python -m rag_agent list-documents --json
```

查看：

```bash
head -1 data/index/documents.jsonl
head -3 data/index/chunks.jsonl
```

思考：

- DocumentRecord 为什么不直接交给聊天模型？
- TextBlock 和 Chunk 有什么区别？
- Markdown 标题路径在哪里保存？

## 3. 实验二：只检索

```bash
python -m rag_agent search "TCP 是怎么建立连接的？" --json
```

检查结果是否包含：

```text
score
chunk_id
source_path
heading_path
text
```

如果结果不对，先改资料、分块或 Embedding，不要先改 DeepSeek Prompt。

## 4. 实验三：查看 RAG 证据上下文

```bash
python -m rag_agent ask "TCP 是怎么建立连接的？" \
  --dry-run --json
```

这一步应看到带 `[1]` 编号、来源和 Chunk ID 的 evidence。它是学习 RAG 最重要的观察点：你可以直接看见模型将要收到什么。

## 5. 实验四：调用 DeepSeek

复制 `.env.example` 为 `.env`，填写自己的 Key：

```dotenv
LLM_API_KEY=sk-你的Key
LLM_BASE_URL=https://api.deepseek.com
LLM_MODEL=deepseek-chat
```

执行：

```bash
python -m rag_agent ask "TCP 是怎么建立连接的？"
```

记录：

- 回答是否只使用资料中的事实。
- `[1]` 是否支持对应句子。
- 改成资料中没有的问题后，是否能够拒答。
- API 错误时 CLI 是否给出可读信息。

不要把真实 Key 写进命令历史、截图、测试或 Git。

## 6. 实验五：改变一个参数

固定同一批资料和问题，只改变 `top_k`：

```bash
python -m rag_agent ask "问题" --dry-run --top-k 3 --json
python -m rag_agent ask "问题" --dry-run --top-k 8 --json
```

再只改变阈值：

```bash
python -m rag_agent ask "问题" --dry-run --min-score 0.05 --json
python -m rag_agent ask "问题" --dry-run --min-score 0.30 --json
```

观察正确证据、噪声和无证据分支如何变化。

## 7. 实验六：增量更新

先导入一次，修改 `sample.md`，再执行：

```bash
python -m rag_agent ingest data/inbox --incremental
```

输出中观察：

```text
documents_added
documents_updated
documents_unchanged
documents_deleted
chunks_reused
chunks_generated
vectors_reused
vectors_embedded
```

再制造一个不可读或超限文件，确认失败清单出现且其他资料仍然可查。

## 8. 实验七：离线评测

创建 `data/eval/retrieval.jsonl`：

```json
{"name":"tcp","query":"TCP 是怎么建立连接的？","relevant_source_paths":["/你的绝对路径/data/inbox/sample.md"]}
```

实际路径必须与 manifest 一致。运行：

```bash
python -m rag_agent evaluate data/eval/retrieval.jsonl \
  --top-k 5 --json
```

先让 Recall@5 稳定，再讨论模型回答质量。

## 9. 实验八：Agent 工具循环

确认普通 `ask` 正常后：

```bash
python -m rag_agent agent "TCP 是怎么建立连接的？" --json
```

观察 JSON 中的：

```text
messages
tool_calls
evidence
step
stopped_reason
history
```

故意把 `--max-steps` 调成 1，观察中止行为和历史是否被污染：

```bash
python -m rag_agent agent "问题" --max-steps 1 --json
```

## 10. 实验九：LangGraph

安装可选依赖：

```bash
python -m pip install -e ".[graph]"
```

运行：

```bash
python -m rag_agent agent "TCP 是怎么建立连接的？" \
  --graph --json
```

对照手写 Agent 的输出，重点确认：

- 节点是否只有 `agent`、`tools`、`finalize`。
- 有工具调用时是否经过 `tools`。
- 无工具调用或达到步数上限时是否进入 `finalize`。
- `AgentResult` 的输出格式是否保持一致。

## 11. 源码阅读顺序

```text
models.py
  -> ingest/pipeline.py
  -> ingest/text.py / markdown.py / pdf.py
  -> chunking/splitter.py
  -> embeddings/base.py / hashing.py / chinese.py
  -> retrieval/index.py
  -> answering/rag.py
  -> answering/chat.py
  -> evaluation.py
  -> agent/knowledge_tool.py
  -> agent/runtime.py
  -> agent/graph.py
  -> cli.py
```

每读一层，写出它的输入、输出、失败方式和测试文件。这样比从 `cli.py` 一路跳函数更容易建立整体理解。

## 12. 要扩展功能时的顺序

### 想支持新文件格式

增加 loader，输出 `DocumentRecord`/`TextBlock`，补充解析和失败测试；不要让回答层直接读取新格式。

### 想提升召回

先补评测问题，再调整分块和 Embedding；保持 `SearchResult` 契约。

### 想增加工具

先定义只读、最小权限的 schema，在 Python 侧校验参数，补工具调用和越界测试，再接入 runtime/graph。

### 想换向量数据库

实现新的索引适配器，保持 provider 校验、`search` 参数和 `SearchResult` 语义，避免上层跟数据库 API 绑定。

## 13. 最终完成标准

- 能从真实目录导入并查看清单。
- `search` 能命中正确来源。
- `ask --dry-run` 能展示完整证据上下文。
- 配置 DeepSeek 后普通 `ask` 能生成带引用的回答。
- 无依据问题会拒答或返回无证据结果。
- 评测集能量化调参变化。
- 资料变化能增量更新，失败不破坏旧版本。
- Agent 工具调用受限、可审计、有步数上限。
- LangGraph 只是编排替代，不改变底层 RAG 契约。
