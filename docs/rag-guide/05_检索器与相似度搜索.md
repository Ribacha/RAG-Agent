# 检索器与相似度搜索

检索器是 RAG 的中间核心：它不负责写答案，只负责从知识库中挑出最可能相关的证据。检索结果质量决定模型有没有机会得到正确资料。

## 1. 一次检索发生什么

当执行：

```bash
python -m rag_agent search "TCP 如何建立连接？" --top-k 5
```

内部过程是：

```text
问题字符串
  -> provider.embed([问题])
  -> 检查 provider 指纹和向量维度
  -> 与索引中每个 Chunk 向量计算余弦相似度
  -> 应用 min_score、source_path、file_type 过滤
  -> 分数降序、chunk_id 稳定排序
  -> 返回最多 top_k 个 SearchResult
```

`SearchResult` 同时带有分数、正文和引用所需的来源字段。

## 2. Top-K 是什么

`top_k` 表示最多取多少条候选证据：

```bash
python -m rag_agent search "你的问题" --top-k 3
```

取值小：上下文更短、噪声更少，但可能漏掉互补证据。

取值大：召回更充分，但可能把相邻重复块和不相关内容交给模型。

Top-K 不是越大越好。它应该通过评测集观察：正确证据是否已经进入前 K，增加 K 后噪声是否明显上升。

## 3. `min_score` 是什么

`min_score` 是最低相似度阈值：

```bash
python -m rag_agent ask "你的问题" --min-score 0.08
```

低于阈值的 Chunk 会被视为没有足够相关性。它是一个拒答保护：宁可告诉用户没有找到依据，也不要把完全无关的资料当成证据。

但不同 Embedding provider 的分数分布不同。不能把一个 provider 的 `0.08` 直接套到另一个 provider。更换 provider 后必须重新在评测集上选阈值。

## 4. 查询过滤

检索器支持按来源和文件类型过滤：

```bash
python -m rag_agent search "三次握手" --file-type pdf
python -m rag_agent search "三次握手" --source "/absolute/path/network.pdf"
```

过滤应该作为权限和范围的一部分设计，而不只是便利功能。后续如果有用户级权限，过滤条件必须在 Python 侧强制执行，不能让模型自己决定可以访问哪个路径。

## 5. 为什么返回原文而不是只返回 ID

检索结果至少要有：

```text
score
chunk_id
source_path
file_type
text
page_start / page_end
heading_path
warnings
```

向量分数只能告诉我们“可能相关”。生成层需要 `text`；用户需要 `source_path`、页码和标题来核验；质量问题需要 `warnings`。

## 6. 相似度排名的局限

单纯的向量相似度可能有以下问题：

- 同一个文档的相邻重复块占满 Top-K。
- 关键词很重要但语义向量没有突出它。
- 表格列关系和代码结构在解析时已经丢失。
- 问题需要多个远距离片段，单次 Top-K 只命中其中一部分。
- 词法基线对同义表达、错别字和隐含关系召回不足。

解决方向可以逐步增加：

1. 更好的 Embedding。
2. BM25/关键词检索，与向量结果做混合。
3. 重排序模型。
4. 按文档、章节或来源做去重和多样性约束。
5. 针对表格、代码和问答资料使用专用解析器。

但每一步都应由评测结果驱动，不要因为技术名词流行就直接引入。

## 7. 从“没有结果”定位问题

执行：

```bash
python -m rag_agent search "问题" --json
```

然后按顺序排查：

### 索引不存在或为空

重新导入：

```bash
python -m rag_agent ingest data/inbox
```

### provider 不一致

错误信息会显示索引和查询的指纹。使用导入时的 provider/model/dimension，或者重建索引。

### 分数太低

先临时降低阈值观察结果：

```bash
python -m rag_agent search "问题" --min-score -1 --json
```

如果完全不相关，说明 Embedding 或分块存在问题；如果正确证据出现，再通过评测选择更合理的阈值。

### 文本本身不对

检查 `chunks.jsonl` 和 manifest。PDF OCR 或编码问题必须在导入层修复。

## 8. 检索器的验收标准

- 对已知问题，相关来源进入目标 Top-K。
- 对完全无关问题，提高阈值后可以返回空结果。
- 同一输入重复运行排名稳定。
- provider 配置不一致时明确失败。
- 结果携带完整原文和引用元数据。
- 过滤条件在应用侧执行，不依赖模型自觉。
