# RAG 的边界与整体架构

## 1. RAG 解决什么问题

聊天模型本身不应该被当成你的文件数据库。它可能不知道你的私人资料，也不应该每次都把整个资料目录塞进请求。RAG 把“知识的保存和查找”放到应用侧，把“根据当前证据组织回答”交给聊天模型。

最小 RAG 可以抽象为两个阶段：

```text
离线/导入阶段：资料 -> 可检索索引
在线/问答阶段：问题 -> 相关证据 -> 回答
```

这里的“离线”不是绝对不能联网，而是指不必在每次提问时重新解析所有文件。导入阶段可以提前完成昂贵工作；问答阶段只处理当前问题和少量证据。

## 2. RAG 和模型微调的区别

| 目标 | 更适合的技术 |
| --- | --- |
| 新增或修改文档知识 | 重新导入并更新索引 |
| 找到正确资料 | 调整解析、分块、Embedding、检索参数 |
| 固定回答格式 | Prompt、输出校验，必要时再考虑微调 |
| 固定工具调用行为 | 工具 schema、状态机、停止条件 |
| 模型长期学习新事实 | 理论上可微调，但成本、时效和数据风险更高 |

对于个人知识库，绝大多数“让 Agent 更懂资料”的需求都应该先做 RAG，而不是训练模型。资料变了只更新索引，模型本身不变。

## 3. 一个可维护的分层

### 3.1 资料层

负责读取 PDF、Markdown、TXT，并尽可能保留来源位置。输出不应该还是任意格式的字符串，而应变成稳定的数据对象。

### 3.2 规范化和分块层

负责统一编码、换行、标题路径和页码，再把过长文本切成适合检索的 Chunk。分块是检索设计的一部分，不是简单的字符串截断。

### 3.3 表示层

Embedding provider 把 Chunk 和用户问题映射到同一个向量空间。只要索引和查询使用同一 provider、模型和维度，才能比较相似度。

### 3.4 索引层

索引至少保存两类信息：

```text
用于计算相似度的向量
用于回答和引用的原文及元数据
```

只有向量没有原文，检索之后无法构造证据；只有原文没有向量，就不能进行当前实现的相似度搜索。

### 3.5 检索层

检索把问题转换成向量，计算与候选 Chunk 的相似度，排序后取 Top-K，并根据 `min-score` 和元数据过滤掉不合格结果。

### 3.6 生成层

生成层把问题和检索结果放进受边界保护的上下文，要求模型只依据证据回答，并从回答中解析 `[1]`、`[2]` 这类引用。

### 3.7 编排层

固定 RAG 是“应用先检索，再调用模型”。Agent 则让模型决定是否调用一个受控工具。LangGraph 进一步把每个节点和路由显式化，但它仍然调用同一个检索工具和数据契约。

## 4. 本项目的两条问答路径

### `ask`

```text
用户问题
  -> Python 调 index.search
  -> build_evidence_context
  -> ChatProvider.complete
  -> 解析引用并打印来源
```

它最适合调试 RAG，因为检索动作固定、输入输出容易对照。

### `agent`

```text
用户问题
  -> 模型决定直接回答或调用 search_knowledge_base
  -> Python 校验工具参数并查询索引
  -> 把工具结果放回消息
  -> 模型继续回答或再次检索
```

它更灵活，但多了一层模型决策，因此排错时应先确认 `ask` 正常。

## 5. 一次问答中必须保留的可观察信息

成熟 RAG 不只返回一段答案，还应该能回答：

- 这次使用了哪个索引和 Embedding 配置？
- 命中了哪些 Chunk，各自分数是多少？
- 每个 Chunk 来自哪个文件、哪一页或哪条标题路径？
- 哪些证据被放进了上下文？上下文是否被截断？
- 模型最终引用了哪些证据？
- Agent 调用了几次工具，为什么停止？

本项目通过 `SearchResult`、索引 meta、`AnswerResult`、Agent state 和 `--json` 输出保留这些信息。

## 6. 从零搭建时的思考顺序

不要从“我要用哪个向量数据库”开始。建议按下面顺序设计：

1. 明确资料类型、规模、更新频率和访问权限。
2. 定义统一的文档、文本块和 Chunk 数据契约。
3. 做一个可重复的解析和分块器。
4. 先用最简单的本地索引验证检索链路。
5. 建立小型评测集，测量检索是否命中。
6. 再接入聊天模型，验证证据是否被正确使用。
7. 最后才决定是否需要更复杂的数据库、混合检索或 Agent 编排。

这样每一层都有独立的输入输出，出现问题时不会把“模型回答差”误判成“向量数据库不行”。
