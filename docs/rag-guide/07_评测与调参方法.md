# 评测与调参方法

RAG 优化不能只看某一次回答。应该把问题拆成可测量的检索指标、生成指标和系统指标，然后一次只改变一个因素。

## 1. 三类指标

### 检索指标

当前项目的 `evaluate` 支持：

- `Recall@K`：相关 Chunk 或来源是否至少有一个进入前 K。
- `citation_accuracy`：返回结果中有多少条匹配标注，是检索层的引用正确率代理。

它们回答的是“正确资料有没有被找出来”，不是“模型有没有正确回答”。

### 生成指标

需要另建问题和答案评测，至少人工检查：

- 答案事实是否被资料支持。
- 是否遗漏关键条件。
- 是否引用了实际支持结论的证据。
- 没有证据时是否拒答。
- 是否把多个来源混成错误结论。

当前仓库没有把外部模型生成自动判分，因为这需要明确的领域标注和评价标准。

### 工程指标

- 单次导入耗时和失败数。
- 查询延迟。
- Embedding/API 调用次数和费用。
- 索引大小和内存占用。
- 失败后是否保留上一版正确结果。

## 2. 评测集格式

每行一个 JSON 对象，至少包含问题和相关标签：

```json
{"name":"tcp-handshake","query":"TCP 如何建立连接？","relevant_source_paths":["/docs/network.txt"]}
{"name":"attention","query":"Query、Key 和 Value 有什么关系？","relevant_chunk_ids":["chunk-attention"]}
```

来源路径必须与索引中的 `source_path` 完全一致。Chunk ID 适合精确测试；来源路径适合文档被重新分块后仍想保留测试意图的情况。

运行：

```bash
python -m rag_agent evaluate data/eval/retrieval.jsonl \
  --top-k 5 --json
```

## 3. 先建立基线

在调整前记录：

```text
资料版本
解析/OCR 配置
分块 max_chars/overlap_chars
Embedding provider/model/dimension
top_k/min_score
Recall@K
典型失败问题
```

没有基线，就无法判断一次改动到底是提升还是偶然。

## 4. 按顺序调参

### 先查解析

检查 `chunks.jsonl`：正文是否完整，编码是否正确，PDF 页码和标题是否保留。原文错误时不要先调模型。

### 再查分块

调整：

```bash
python -m rag_agent ingest data/inbox \
  --max-chars 800 --overlap-chars 80
```

观察答案所需的最小证据是否经常被切开。

### 再查 Embedding

比较 `hash`、`chinese` 或一个真实神经 Embedding provider，保持资料和评测集不变。

### 再查检索参数

比较 `top_k` 和 `min_score`。先扩大召回看正确结果是否出现，再提高阈值控制噪声。

### 最后查 Prompt 和模型参数

当正确证据已经稳定进入上下文，但回答仍不符合要求，才修改 system prompt、temperature 或 max tokens。

## 5. 典型失败模式和定位

| 现象 | 最可能的层 | 优先检查 |
| --- | --- | --- |
| `search` 找不到答案 | 解析/分块/Embedding/阈值 | chunks、provider、min_score |
| `search` 正确但 `ask --dry-run` 不正确 | 参数或索引配置 | top-k、阈值、过滤 |
| dry-run 正确但模型答错 | Prompt/模型生成 | evidence 边界、引用要求、模型参数 |
| 模型回答有引用但事实错 | 检索或引用使用 | 证据是否真的支持句子 |
| 新文件加入后旧资料消失 | 增量合并/索引更新 | manifest、source scope、失败处理 |
| 运行时要求安装无关依赖 | 包边界 | 可选依赖是否惰性导入 |

## 6. 阈值实验

对同一批问题试几个阈值：

```text
0.00, 0.05, 0.08, 0.15, 0.30
```

记录两件事：

- 正确问题的召回率有没有下降。
- 陌生问题是否更容易被拒答。

阈值不是越高越安全。过高会把真实证据全部过滤掉；过低会把噪声送进 Prompt。

## 7. 离线测试的价值

当前仓库的测试覆盖：

- 解析、编码和 OCR 降级。
- 分块边界和稳定 ID。
- provider 确定性、维度和配置隔离。
- 索引构建、排序和过滤。
- RAG 无证据分支和引用解析。
- CLI 端到端闭环。
- Agent 工具参数校验、历史和 LangGraph 节点。

运行：

```bash
python -m pytest -q
```

测试的作用是保护契约；评测集的作用是反映你的真实资料质量。两者不能相互替代。

## 8. 做对照实验

一个有效实验只改变一个主要变量：


```text
实验 A：hash -> chinese，其他不变
实验 B：max_chars 800 -> 1200，其他不变
实验 C：top_k 5 -> 8，其他不变
```

每次保存配置和结果。否则即使 Recall@K 变化，也不知道原因。

## 9. 评测完成的验收标准

- 有固定的代表性问题集和独立验证问题。
- 检索和生成指标分开记录。
- 有无证据问题，测试拒答行为。
- 每次调参能回到具体失败样本。
- 资料、索引和配置版本可追踪。
- 结论不把 `citation_accuracy` 夸大为模型事实准确率。
