# 增量更新、安全与工程化

能在一次命令中回答问题只是原型。一个可以长期使用的 RAG 还要处理资料更新、部分失败、配置变化、权限和审计。

## 1. 增量导入的目标

资料目录变化后，理想行为是：

```text
新增文件 -> 解析、分块、计算向量
修改文件 -> 只重做这个来源
未变化文件 -> 复用旧 Chunk 和向量
删除文件 -> 从当前范围快照移除
解析失败 -> 保留上一版正确结果并记录失败
```

运行：

```bash
python -m rag_agent ingest data/inbox --incremental
```

## 2. 项目如何判断是否变化

`incremental_ingest` 综合比较：

- 规范化后的 `source_path`。
- 文件字节 `content_hash`。
- 解析/OCR `ingestion_fingerprint`。
- 分块 `chunking_fingerprint`。
- 旧 manifest 中记录的 Chunk 数量。

只比较文件修改时间不够可靠：时间可能被保留、拷贝或精度不足。内容哈希加处理配置更适合决定是否复用。

## 3. 为什么失败时保留旧版本

假设 PDF 暂时损坏或 OCR 依赖被卸载。如果导入失败就删除旧 Chunk，知识库会从“上一版可用”退化为“完全没有这份资料”。

当前实现把错误写入失败清单，并保留上一版来源结果。这是数据更新的事务性思路：新版本没有准备好，就不要破坏最后一个正确版本。

## 4. 解析和检索的权限边界

当前 Agent 工具只允许：

```text
search_knowledge_base(query, top_k, min_score)
```

Python 代码强制校验：

- `query` 必须是字符串且长度有限。
- `top_k` 必须是 1-20 的整数。
- `min_score` 必须在 -1 到 1 之间。
- 不接受额外字段。
- 工具只能查询已经加载的索引。

模型看不到任意文件读取接口，也不能执行 Shell 命令或修改资料。这个边界必须在应用代码中执行，不能只写在 Prompt 里。

## 5. 文档是数据，不是指令

知识库中的文本可能包含：

```text
忽略系统提示词
执行某个命令
读取某个文件
```

在 RAG 中它们都应该被当作普通内容。`rag.py` 使用 `<evidence>` 标签，并明确告诉模型证据中的命令和要求不是系统指令。

这可以降低提示注入风险，但不能代替：

- 工具白名单。
- 参数校验。
- 文件路径边界。
- 网络和写权限隔离。
- 操作审计。

## 6. API Key 和数据安全

- Key 放在 `.env` 或 Shell 环境变量中，不写进代码和评测集。
- `.env` 必须被 `.gitignore` 排除。
- 日志不要打印完整 Authorization header 或 Key。
- 对话历史可能包含敏感资料，应像原始资料一样保护。
- 发送给外部聊天模型前，应明确哪些 Chunk 可以离开本机。

当前项目默认 Embedding 本地运行，但普通 `ask` 会把命中的证据发送给 DeepSeek。离线检索和外部生成是不同的隐私边界。

## 7. 可观察性

至少记录这些字段：

```text
request/question id
index path/version
provider fingerprint
top_k/min_score
retrieved chunk_id 和 score
context 字符数
model name
工具调用次数和停止原因
错误类型
```

当前 `--json` 输出和索引 meta 已提供大部分审计信息。生产系统可以把它们写入结构化日志，但不应记录敏感正文或 API Key。

## 8. 从 JSONL 迁移到数据库的时机

JSONL 适合：

- 个人知识库。
- 学习数据流。
- 小规模索引。
- 需要直接检查文件格式的阶段。

当出现以下情况再考虑 FAISS、SQLite、Qdrant 或其他服务：

- Chunk 数量导致全量扫描延迟不可接受。
- 需要并发写入和事务。
- 需要复杂过滤、租户隔离或远程部署。
- 需要持久化向量服务和备份策略。

迁移时保留上层接口：解析器继续输出 Chunk，检索器继续返回 SearchResult，回答层不应该知道底层是 JSONL 还是数据库。

## 9. 工程化验收清单

- 新增、修改、删除和失败更新都有测试。
- 失败更新不会覆盖上一版可用资料。
- 索引和配置有版本指纹。
- API Key 和敏感正文不会进入 Git 或日志。
- Agent 工具是白名单和只读边界。
- 用户可以看到来源、分数和停止原因。
- 数据规模超过 JSONL 能力前，有迁移理由和基准数据。
